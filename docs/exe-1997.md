# The 1997 Windows executable (reference only)

No longer the recompilation target -- see [exe-2002.md](exe-2002.md). Kept for
comparison: unlike the 2002 build it has a full relocation table.

`GTAWIN/Grand Theft Auto.exe` from the original CD.
SHA-1 `038561860ce80eda794a491935d64878f925376e`, 909,824 bytes.

Reproduce everything here with:

```bash
python3 -m venv .venv && .venv/bin/pip install -r tools/requirements.txt
python3 tools/unpack.py "game_data/GTAWIN/GRAND THEFT AUTO.EXE" gen/analysis
.venv/bin/python tools/funcs.py gen/analysis
```

## Image

* PE32 GUI, linked 1997-10-10 with Microsoft linker 4.20 (Visual C++ 4.2),
  CRT statically linked.
* Image base `0x400000`, entry `0x4AE640` (CRT `WinMainCRTStartup`).
* **Full base-relocation table: 30,890 HIGHLOW fixups.** Every pointer stored
  in the image is known, which is what makes static recompilation tractable.

| Section | VA | Virtual size | Raw size | Perms |
| --- | --- | --- | --- | --- |
| `.text` | `0x401000` | `0xB69A0` | `0xB6A00` | r-x |
| `.rdata` | `0x4B8000` | `0x288A` | `0x2A00` | r-- |
| `.data` | `0x4BB000` | `0x2CB8F0` | `0xEC00` | rw- (≈2.9 MB, mostly BSS) |
| `.idata` | `0x787000` | `0x12BC` | `0x1400` | rw- |
| `.rsrc` | `0x789000` | `0x8AC` | `0xA00` | r-- |
| `.reloc` | `0x78A000` | `0x13EA0` | `0x14000` | r-- |

## Libraries

Static imports: 171 functions from 8 DLLs.

| DLL | Functions | Role |
| --- | --- | --- |
| `mss32.dll` | 45 | Miles Sound System: samples, streams, timers, Red Book CD audio |
| `smackw32.dll` | 8 (by ordinal) | Smacker video |
| `DPLAYX.dll` | 2 (by ordinal) | DirectPlay multiplayer |
| `KERNEL32.dll` | 61 | files, heap, CRT support |
| `USER32.dll` | 29 | window, messages, cursor, `GetKeyState` |
| `GDI32.dll` | 20 | palette, DCs, blits |
| `ADVAPI32.dll` | 4 | registry (settings) |
| `WINMM.dll` | 2 | `joyGetPosEx`, `joyGetDevCapsA` |

**Graphics are not a static import.** The game statically links
**SciTech MGL** (MegaGraph Graphics Library), which picks a backend at run
time and loads it with `LoadLibraryA`/`GetProcAddress`:

* DirectDraw — `ddraw.dll`: `DirectDrawCreate`, `DirectDrawCreateClipper`
* WinG — `wing32.dll`: `WinGCreateDC`, `WinGCreateBitmap`,
  `WinGSetDIBColorTable`, `WinGBitBlt`, `WinGStretchBlt`
* WinDirect — `WDIR32.DLL` (full-screen VESA)
* the internal `*.DRV` names (`DDRAW8.DRV`, `LINEAR8.DRV`, `WINDC.DRV`,
  `3DFX.DRV`, `OPENGL.DRV`, …) are MGL's built-in driver table, not files.

The 23 exports (`_glWindowPos*MESA`) come from the Mesa OpenGL code bundled
with MGL; the game does not use them itself.

Input uses window messages, `GetKeyState` and WinMM joystick calls — there is
no DirectInput.

## First-pass function discovery

Recursive descent from the entry point, exports, code pointers in data and
code addresses used as immediates; jump tables are sized exactly from the
relocation table.

| | |
| --- | --- |
| Functions | 2,338 |
| Instructions | 215,486 |
| Jump tables | 345 (3,689 entries) |
| `.text` covered | 728,795 / 747,936 bytes (**97.4 %**) |
| Remaining | ~14.6 KB padding, ~4.5 KB unexplained |

Known gaps: 16 imports are reached only through `mov reg, [__imp_X]; call reg`
(e.g. `PeekMessageA`), which the first pass doesn't track yet, and 6
functions run into undecodable bytes (data in code, to investigate).
